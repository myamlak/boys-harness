# The paper's own pair inside an H2O workload — measured verdict

**Verdict: the bar is not met.** The crossover paper's model, run through its own two routes inside
an integral engine on H2O in STO-3G, 6-31G* and cc-pVTZ, does not beat always-direct in either metric
under the referee's bar — not on the full metric, and not on any reading that survives deleting a
single comparison with a deciding order n >= 1. The only full-metric advantage is the B1 order-0
comparison the bar excludes (+4.60723% on STO-3G, whose deciding cell is order 0 and whose deletion
leaves an exact tie in the absolute metric and a 3.8906% deficit in the relative reading); on
6-31G* and cc-pVTZ the same comparison is *worse* than always-direct (-10.4641% and -2.54094%), so
even the excluded advantage is a property of one basis's argument stream and not of the policy. The
relative metric ties on all three bases, because its worst cell is always one where the model takes
the fallback. The seven relative-metric ship cells do win where they apply, by up to +48.22% (STO-3G),
+88.55% (6-31G*) and +90.86% (cc-pVTZ), but the paper's metric is the worst cell, and the worst cell
is not one of them: the run supports a cell-level guarantee, not an end-to-end claim. The workload
reproduces the sweep-level failure rather than repairing it.

## Reachability

The host engine cannot select either route per order: the ERI path reaches Boys through
`MdBoysBatch<T, kFp64Seeds>` (`integrals/src/internal/md_boys.hpp`), whose fp64 arm calls the
unqualified `BoysAllOrders(nmax, x, out)` — the library's default class row, a third route — and the
host never calls `BoysRegionAProduct` anywhere under `integrals/`, `scf/` or `grid/`. A per-order
selector inside that one function, signature unchanged, reaches both ERI call sites; the scratch
implementation is `md_boys.hpp` here (about 154 lines of the file, no public API, caller or build
option changed). Small in code, structural in cost: the library publishes no single-order product
entry, so a per-order mix built from the published entries must form both all-orders ladders at every
argument, and the probe's wall clock says nothing about the paper's one-evaluation-per-argument cost.
A cost-faithful run needs that single-order product entry, which is library debt and not a boundary.

## Method

Six arms, one dense ERI tensor each, from one build: the paper's named recursed policy; the
matrix-product direct entry; and four model arms (metric absolute/relative × population band/
population-limited) that apply the paper's margin-1 states with an always-direct fallback. The
states come from the paper tree's own `sweeps/amplification_form/results/prediction.csv` (132 rows,
8 ship, 59 product, 65 abstain, 67 commitments). Each emitted ladder is asserted against the arm's
stated selection while streaming (0 mismatches). Every Boys value is compared with an 80-digit
mpmath reference (worst relative deviation 1.95135e-75 at its own validation); the tensors and
energies are compared between arms, with the trace identity Tr[DH] + E_2e against the SCF electronic
energy checked at both densities (largest residual 2.7000623958883807e-13, cc-pVTZ). RHF at default
and tight gates; all arms converge.

## What is deposited

- `md_boys.hpp` — the scratch seam, and `md_boys.diff` against the host's file.
- `pair_probe.cpp`, `pair_analyze.py`, `pair_selftest.py`, `bridge-CMakeLists.txt` and
  `integrals-CMakeLists.diff` — the probe, the analyzer, its self-test and the build entries.
- `records/<basis>/` — `analysis.txt` (every number quoted above), `probe.log`, the per-arm
  `summary.txt` (counts, seed and fixed-density energies, SCF traces, trace-identity residuals),
  `trace.txt` (SCF convergence), `eri_max.txt`, and `boys_record.txt`.

Not deposited, and why: the dense ERI tensors (259 MB per arm on cc-pVTZ) and the per-arm argument
streams (18 MB per arm) are regenerated by the deposited probe; the SCF density dumps likewise.

## Regeneration

The probe is a target of the bladawiec tree with the two CMakeLists changes applied and the scratch
`md_boys.hpp` in place, configured with the MD bridge probes on and `QCX_INTEGRALS_LMAX=2`; the
self-test is `python pair_selftest.py`; each basis is one probe run followed by
`python pair_analyze.py <run-dir> <out>` (mpmath 1.4.1 needed; the analyzer exits 77 in Python's
isolated mode because that hides user-site mpmath). The exact commands, exit codes and digests are
in the paper tree's WORKLOAD-PAIR.md, section 10.

## Caveats

The run is CPU fp64 only, H2O only, margin 1 only, and is not a cost measurement; the F_0-scaled
accuracy contract is not the scoring metric (the paper's own bare |err|/|F_n| is). The probe's
first (LMAX = 2) build recorded no exit codes; the LMAX = 3 rebuild and the invariance check did
(0), and the invariance check showed the numeric outputs do not depend on LMAX at these arguments.
