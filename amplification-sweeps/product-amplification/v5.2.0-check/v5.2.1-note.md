# The v5.2.1 source-identity confirmation

The check in this directory was run at boys v5.2.0. The current release is
v5.2.1. This note answers the question the current release raises: do its
evaluation sources differ from the sources the v5.2.0 check compiled and from
the historical v5.1.1 sources the paper's figures were measured with? It is a
source-identity comparison, not a new execution check; the compiled and run
check remains the v5.2.0 one recorded in `README.md`.

## The evaluated files

The evaluated path is the 62 files under `include/boys` and the 14 files under
`src`, the same 76 files the v5.2.0 check compared. The comparison is by git
blob SHA-1 and by content SHA-256, file by file:

- v5.2.1 against v5.2.0: 75 of the 76 files are byte-identical, one differs.
- v5.2.1 against v5.1.1: 75 of the 76 files are byte-identical, one differs.
- The one differing file is `include/boys/version.hpp` in both comparisons.

`include/boys` has 62 files: 61 are identical to both v5.2.0 and v5.1.1, and
`version.hpp` is the 62nd. `src` has 14 files: all 14 are identical to both.

The `version.hpp` change is only the version constant:

- against v5.2.0: `kVersionPatch` 0 to 1 and `kVersionString` "5.2.0" to
  "5.2.1"; no other line differs.
- against v5.1.1: `kVersionMinor` 1 to 2, `kVersionPatch` 1 to 1, and
  `kVersionString` "5.1.1" to "5.2.1"; no other line differs.

The SHA-256 of the three `version.hpp` blobs are v5.2.1
`df58228304830d23341e23c549baf3b5a7f32b2e9ba766df76ee4c02f2837623`,
v5.2.0 `ac7352ed90bbc4fc615387e6fe8289b5cc26dc596e361c484f8adb3955b3b2a6`,
and v5.1.1 `48900211c5286230a2873c74dc07fc978b0d873a06d67bb0f6fc7d146edf9aba`.
The full file-by-file table is in `v5.2.1-sources-compare.txt`; the 76
SHA-256 values of the v5.2.1 files are in
`evaluation-sources-v521.sha256`. The v5.2.0 and v5.1.1 columns of that table
reproduce the 76 values in `evaluation-sources-compare.txt` exactly.

## What changed outside the evaluated path

The v5.2.1 tree has 710 files, the same count as v5.2.0. Against v5.2.0, 10
files are modified, none is added and none is deleted; the other 700 are
byte-identical. The 10 are:

- `include/boys/version.hpp` --- the version constant above.
- `tests/boys_accuracy_gate.cpp` --- the two half-lane gate-row statements
  `LC.half.vacuous_floor` and `code.half_domain_stop`, and their source
  anchors, now naming `include/boys/boys_decl.hpp`.
- `docs/lane-contract.md` --- the sentence on the partition book's carrying
  fraction.
- `tests/data/boys_accuracy_gate_run.txt` and
  `tests/data/boys_option_probe_report.txt` --- the gate and probe records
  re-made at v5.2.1.
- `CHANGELOG.md`, `CITATION.bib`, `CMakeLists.txt`, `README.md` and
  `docs/specification.md` --- the release's version and citation metadata.

Against v5.1.1, 13 files are modified and three are added (the
`tests/data/half-sweep/` files that entered at v5.2.0); 694 of the 707 v5.1.1
files are byte-identical. The full list is in `source-diff-v521.txt`.

None of the changes is under `src`. The only change under `include/boys` is
`version.hpp`. The two sweeps compile `sweep1.cpp` and `sweep2.cpp` against
the `include/boys` headers with the runbook's direct `cl` line; the
integral-engine bridge compiles `src/boys.cpp`, `src/boys_c.cpp`,
`src/boys_orders_simd.cpp`, `src/boys_probe.cpp` and `src/boys_simd.cpp`. The
changed gate, test-data, documentation and metadata files are not on either
compile path, and the version constant is read only by `VersionString()` and
the probe record's protocol line, not by any evaluation arithmetic. No source
the sweeps compile changes from v5.2.0 to v5.2.1.

## What this means for the paper

The execution check remains the v5.2.0 check: it compiled and ran both sweeps
and the bridge at v5.2.0, and its records are in this directory. The v5.2.1
comparison shows that the current release's evaluation code is the same code
apart from the version constant, so the check's result carries over to
v5.2.1. The paper's figures remain the historical v5.1.1 run's figures, for
the reason the v5.2.0 check established: the evaluation sources are
byte-identical apart from the version constant. The current release is
v5.2.1, tag v5.2.1, commit b51efb4; v5.2.0 is the tag the execution check was
run at, not the current release.

The v5.2.1 tree was not compiled or run in this check. The check's binaries,
records and compiler identity are the v5.2.0 ones; this note establishes only
that the evaluation sources they were built from are unchanged in v5.2.1.
