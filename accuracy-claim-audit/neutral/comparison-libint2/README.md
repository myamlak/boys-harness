# Boys function accuracy comparison

An accuracy-only comparison of the Boys-function library at tag `v5.3.2` with
libint2 2.13.1, on the two reference grids committed in the Boys repository.
No timing was measured. The Boys repository and the gate-audit tree were read
only; neither was modified.

## Implementations and revisions

| Implementation | Revision evidence | Entry points compared |
|---|---|---|
| Boys library | annotated tag `v5.3.2` is tag object `058f10f273f37ca3b5769e9f1173c218f38fce6c`, pointing to commit `6739447d82765ae5f7f68351a99f418cd018dd9a`, tree `71be8196d53c31c8ec5d9be2c9fb48453b297c4e`; `git diff --quiet v5.3.2` exits 0, so the tracked tree equals the tag | `boys::BoysAllOrders` (single-argument ladder) and `boys::BoysAllN` (order-major batch), both the default double lane, orders 0..32 |
| libint2 | `LIBINT_VERSION "2.13.1"` in `inst/include/libint2/config.h`; the release is not a git checkout (no `.git`), so the version is the installed header's own statement | `libint2::FmEval_Chebyshev7<double>` (the production evaluator libint2's operator traits select) and `libint2::FmEval_Reference2<double>` (libint2's own "reference" evaluator) |

No other Boys implementation was already on the machine: there is no libcint
or other Boys library, and Boost.Math (the only other special-function package
present) has no Boys function. The Boys repository's Boost external gate
concerns Airy functions, not Boys, and was not reused. libint2 is therefore the
only external implementation in this record, with two evaluators.

Both generators are recorded in `digests.txt`. The probe reads only the first
three columns (`n`, `x`, `value`). It parses the reference value with
`std::strtold` into an x86-64 80-bit long double, so reference rounding is not
charged to either implementation. The two grids were cross-checked at their
1,254 common `(n, x)` cells with Python `Decimal` at 80-digit precision: worst
absolute difference `4.968e-26`, worst relative difference `4.941e-25`, verdict
AGREE (`grid-crosscheck.txt`, exit 0). This is consistent with the 25-digit
grid's own precision and is evidence against a transcription or generation
error in either grid.

## Bounds compared against

* **Boys library.** Its specification states the double-lane contract
  `max(1e-13 * F_n(x), 1e-13 * F_0(x))`. Since `F_n(x) <= F_0(x)` for `x >= 0`,
  this is `1e-13 * F_0(x)`, and that is the per-cell bound the probe applies,
  using the grid's own reference `F_0(x)`. The specification binds above the
  lane's smallest normal, `2^-1022` (`DBL_MIN =
  2.2250738585072014e-308`); below it the returned value may be subnormal or
  zero and no accuracy is claimed. Cells whose reference is below `DBL_MIN`
  are counted but excluded from the pass/fail domain.
* **libint2 `FmEval_Chebyshev7`.** No accuracy bound is published. The header
  documents the method (7th-order Chebyshev interpolation) and a constructor
  argument, "the desired relative precision", defaulting to
  `std::numeric_limits<double>::epsilon()` and rejecting anything smaller. A
  desired precision is not an achieved bound, and no achieved bound is stated
  anywhere in the header. This record therefore reports the measured worst
  absolute error against the reference and says `no published bound`; the ratio
  to the Boys contract is context only and is not a libint2 claim.
* **libint2 `FmEval_Reference2`.** The header states: "Precision is not always
  guaranteed as it is limited by the precision of Real type. When Real is
  double, can maintain absolute precision of epsilon for up to m=40." That is
  an approximate statement, and the header itself disclaims a guarantee. The
  probe checks it per cell against `1 * DBL_EPSILON` absolute.

## Error definition

For every cell, error is `|computed binary64 value - reference value|`. The
Boys ratio is `error / (1e-13 * F_0(x))`. The libint2 Reference2 figure is
`error / DBL_EPSILON`. A zero return is not by itself a failure: it is
forbidden only when the true value exceeds the cell's bound, which is the
gate's own rule. All numbers below come from the probe output in
`results-all.tsv` (machine-readable, full probe precision: `%.17g` binary64
values and arguments, `%.17Le` long-double ratios, reference column as
committed) and `raw-gate-grid.txt` / `raw-45digit-grid.txt`.

The two Boys lanes are bit-identical at every cell on both grids: "boys single
vs batch differing cells: 0". The worst Boys error is the cell the Boys
specification itself documents: reference `3.282257529495611860821142e-15`,
returned `7.8634896378733907e-15`, error `4.582e-15`, which is 1.396 times the
value and 0.288 of the bound; the specification says 1.40 times the value and
0.288 of the bound. The probe therefore reproduces the library's own published
gate figure exactly, which validates the probe, build and reference parsing.

## Two behaviours a reader should not misread

* **Zeros below the bound are allowed.** In the contract domain on the gate
  grid the Boys lanes return zero at 27 cells; every one has a true value below
  the cell's `1e-13 F_0` bound, so none is a forbidden zero (forbidden zeros:
  0). Chebyshev7 and Reference2 return a non-zero value at those cells. This is
  the documented far-ladder flush, not an accuracy failure. All 59,301 rows,
  including the 3,777 below `DBL_MIN`, satisfy `error <= 1e-13 F_0` for every
  arm.
* **A large relative error is not a contract violation.** The Boys worst
  relative error is 1.396 on the gate grid (n = 32, x = 31) and 0.792 on the
  45-digit grid (n = 32, x = 33). Both cells satisfy the ladder-scaled absolute
  bound with room to spare (0.288 and 0.0295 of the bound). The contract is
  `1e-13 F_0(x)`, not a relative figure on `F_n(x)`; the specification states
  this and lists the cell families that need the wider arm.

## What could not be compared, and why

* **No published bound for libint2 Chebyshev7.** No "error / published bound"
  number exists for it. Its measured worst absolute error against the committed
  reference is reported instead, and its relation to the Boys contract is
  marked as context, not as a libint2 bound.
* **Reference2's epsilon figure is approximate.** The header says precision is
  "not always guaranteed"; it is exceeded at 46 of 55,524 gate-grid contract
  cells (worst 1.807 eps) and 1 of 2,904 45-digit cells (1.523 eps). It is
  reported as a documented figure with its own result, not as a broken
  guarantee.
* **No second external library.** Nothing else on the machine implements the
  Boys function, so the comparison is the Boys library against two libint2
  evaluators, not against two independent external projects.
* **libint2 has one further double evaluator not run here.** `FmEval_Taylor` is
  an alternative interpolation evaluator; libint2's operator traits select
  `FmEval_Chebyshev7` for double, so Chebyshev7 is the production path, and
  Taylor's header likewise states only a desired precision and no achieved
  accuracy bound. The header's one "guaranteed absolute precision" warning of
  1.4e-14 belongs to `TennoGmEval` (the Yukawa/exponential kernel), not to the
  `FmEval_*` Boys evaluators, so it is not a Boys bound.
* **One host configuration.** All runs use WSL Linux x86-64, g++ 15.2.0
  (Ubuntu 15.2.0-16ubuntu1), `-std=c++20 -O2 -mavx2 -mfma`. The Boys double
  lanes are the default build; a different compiler, ISA tier or
  multiply-add route could move the last bits. The measured margins are not
  near zero: the Boys worst is 0.288 of its bound, and libint2's worst measured
  errors are of order 1e-2 to 1e-3 of the Boys contract.
* **Accuracy only.** No timing, throughput or memory was measured. The task
  excluded them.
* The Boys checkout contains untracked local log files from earlier work; the
  tracked tree is identical to tag `v5.3.2` (`git diff --quiet` exit 0), and
  the compared data files are the tag's tracked files with the digests above.

## Reproduction

Requirements:

- WSL Linux x86-64, or another Linux x86-64 host: the probe parses the
  reference with an 80-bit `long double`, and the libint2 static archive is an
  ELF Linux build.
- g++ 15.2.0 (C++20), invoked with
  `-std=c++20 -O2 -mavx2 -mfma -Wall -Wextra`.
- A boys `v5.3.2` checkout. `checks/run-all.sh` takes it from `BOYS_SOURCE`;
  the default is `../boys` beside this repository.
- A libint2 2.13.1 install tree with `inst/include/libint2` and
  `inst/lib/libint2.a`. Set `LIBINT_ROOT` to that tree; the script exits with
  a message when it is unset.
- Python 3 for `checks/compare_grids.py` (standard library only).

From the repository root (Git Bash needs path conversion off for `wsl`; WSL
starts in the translated current directory, so the script path is clone
relative):

```
MSYS_NO_PATHCONV=1 wsl -e sh -c \
  'BOYS_SOURCE=/mnt/c/path/to/boys-v5.3.2 LIBINT_ROOT=/mnt/c/path/to/libint-2.13.1 sh accuracy-claim-audit/comparison-libint2/checks/run-all.sh'
```

The recorded run exited 0. Key steps and their recorded exit codes: compile
probe 0; gate-grid run 0; 45-digit-grid run 0; grid cross-check 0; all file
assembly steps 0. The exact commands, outputs and exit codes are in
`commands-and-exit-codes.txt`.

`digests.txt` and `commands-and-exit-codes.txt`, and the generated
`build-command.txt` and `build-warnings.txt`, name the measurement tree's
paths. The deposited copies of `checks/run-all.sh` and
`checks/compare_grids.py` differ from the measured copies only in path
handling, so the two script lines in `digests.txt` do not hash the deposited
copies; every reference, library, result and conclusion is unchanged.
