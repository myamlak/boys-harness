csh_fast.c, line 619 (sinh_ru) and line 671 (sinh_rd):

  if (y.d > max_input_csh.d) { /* out of range */

The guard is a strict inequality, so the double equal to max_input_csh.d
is not caught here and reaches the accurate path.

csh_fast.c, line 706 (sinh_rd), the last line of the accurate path:

    return 1024. * res.d;

The multiplication is a hardware binary64 operation in the caller's
rounding mode, which is round-to-nearest unless the caller changed it;
crlibm does not set it.  At the named input the intermediate overflows,
so this line yields +infinity where directed rounding requires
+DBL_MAX.
