SUMMARY

The gate's internal individual-bound row catches the reintroduced defect; the
ordinary non-gate suite does not. The historical v1.1.4 arithmetic was
reintroduced in the v5.3.4 copy as a line-count-neutral, one-expression change
to RegionBSimdHalf (f = f * (1/x) instead of f = f / x; src/boys_simd.cpp
SHA-256 ea2d971bc8a642c3c6e7c8c83149b21dc8c7f21294dec2c6da9b8904ac6cb0c1;
the clean gate binary at v5.3.4 is
6b023a2e7924c61054b7f687f256dec72250f46285f5a1be9e52c85a6d04bfd1).
After the incremental rebuild
(cmake --build boys-v5.3.4/build-gate --target boys-accuracy-gate boys-tests --config Release,
exit 0, 16 s), boys-accuracy-gate --strict exited 1 in
13 s. It reported EXCEEDED for lane fp16 simd-half, region B, at n = 32,
x = 11.944741727643702: err = 1.53895e-07, bound = 1.29802e-07, ratio = 1.186,
ref = 1.53895e-07; the error equals the whole reference, so the vector return
is zero. The failing rows are code.half_simd_cells ("worst 1.19 of budget at
(n=32, x=11.9447): delivered 1.539e-07 against 1.298e-07") and
code.half_domain_stop (1 point returned the format's zero, largest value so
discarded 1.539e-07); the claim book falls to 36 of 39 met with 2 exceeded.
The pair-sum row code.half_simd_budget stays Verified, but its own evidence
prints the forbidden zero as a diagnostic (1 cell where a path returned zero
above its own bound; 1 body-out cell at 1.186 of its bound) and states that
those counters do not decide its verdict. The same tree's ordinary suite,
ctest -R "^(boys-tests|boys-no-vector-fallback)$", exited 0 in 77 s (both
tests passed), and the direct vector-vs-scalar tests,
boys-tests.exe --gtest_filter=BoysTest.SimdMatchesScalarF16:BoysTest.SimdMatchesScalarBf16,
passed (2 tests, 3 ms): they sample n = 8 and region-B arguments from
[11.95, 28.95), so the n = 32, x = 11.9453125 point is outside their sample.
The gate's CTest entry failed on the same mutation (exit 8, 11.80 s). A
separate observation: changing the comment's line count instead of only the
expression shifted the P10 anchor (quote lines 635-638 against anchor
634-637) and made the gate exit 2 on registration before reporting verdicts;
the line-count-neutral mutation avoids that confound. Mutation 2
(kFlatMonoCoeffs first coefficient 9 -> 8) reproduced the harness record's gate
result exactly: exit 1, three exceeded rows (README.double.single,

certified, claim book 35 of 39. Its ordinary-suite run was started and stopped
after 56 s without a pass/fail result, so only the gate outcome is reported for
mutation 2. Two factual notes about the audited revision:
the paper's main text calls the defect point "order-0" whereas supplement S6
Record 1, the gate grid and the probe place it at n = 32; and supplement S6
Record 1's scalar return of 5.96046e-8 differs from the v5.3.4 scalar entry's
1.7881393432617188e-7 at the same stored-half argument, while the vector zero
and the threshold arithmetic are unchanged.
